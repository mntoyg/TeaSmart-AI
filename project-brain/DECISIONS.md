# DECISIONS (บันทึกเหตุผล ห้ามลบ ให้ต่อท้ายเท่านั้น)

## D-001 Frontend เป็น Vite + React + TS, CSS ธรรมดา
เหตุผล: เรียบง่าย deploy ได้ทันที

## D-002 ข้อมูลโรคมีแหล่งเดียว
เหตุผล: แก้ข้อมูลครั้งเดียวทุกหน้าตรงกัน ตรวจสอบกับผู้เชี่ยวชาญง่าย
ในแอป `frontend/` แหล่งนั้นคือฐานความรู้ที่ backend เสิร์ฟ (`/api/v1/kb` และสำเนาใน `frontend/public/api/v1/kb`)
ส่วน `src/data/diseases.ts` ใช้กับหน้าตัวอย่างที่ราก repo เท่านั้น

## D-003 ผล Demo ต้องติดป้าย Demo เสมอ
เหตุผล: โหมด Demo เคยคืนค่าคงที่ "ใบไหม้น้ำตาล 92.4%" ทุกภาพ
(ผู้ทดสอบเคยส่งภาพใบปกติแล้วได้ใบไหม้น้ำตาล 92.4% — นั่นคือผลคงที่ ไม่ใช่โมเดลผิด)
ห้ามเดโมต่อกรรมการโดยไม่บอกว่าเป็น Demo จนกว่าจะเชื่อมโมเดลจริง

## D-004 ความมั่นใจต่ำ = ไม่ฟันธง
เมื่อ confidence ต่ำกว่า `min_confidence` (ค่าจาก `/api/v1/config` ปัจจุบัน 0.60 ปรับได้หลังทดสอบกับโมเดลจริง)
แสดง "ยังไม่แน่ใจ" พร้อมคำแนะนำถ่ายใหม่ และไม่โชว์ขั้นตอนใช้สารเคมี

## D-005 ใช้ Command registry กลาง
เหตุผล: ปุ่ม/คีย์ลัด/palette ใช้ action เดียวกัน ไม่ซ้ำโค้ด

## D-006 ไม่เพิ่ม library สำหรับ palette
เขียนเอง (ใช้ role="dialog") เพื่อคุมขนาด bundle และ a11y
(ถ้าอนุมัติ lib ใดภายหลังให้เขียนต่อท้ายตรงนี้)

## D-007 ประวัติไม่เก็บภาพต้นฉบับ
เหตุผล: ลดพื้นที่และความเป็นส่วนตัว ภาพจะอยู่ในคิวเฉพาะตอนรอส่งเซิร์ฟเวอร์เท่านั้น

## D-008 เว็บสาธารณะคือแอป `frontend/`
เหตุผล: repo มีสองหน้า — `frontend/` ที่โหลดโมเดล ONNX บนเครื่องและเรียก `/api/v1/scan`
กับหน้าตัวอย่างที่ราก repo (`src/`) ซึ่งไม่มีโมเดลและสุ่มผล งานทุกเฟสต่อจากนี้ทำใน `frontend/`
เพื่อให้ฟีเจอร์ใหม่อยู่บนแอปที่ให้ผลจริง / ผลกระทบ: `vercel.json` ชี้ `root: frontend`,
เอกสารใน project-brain อ้างพาธภายใต้ `frontend/src` / วันที่ 2026-11-03 / ตัดสินใจโดยทีม frontend
หลังพบว่าเว็บเคยขึ้นหน้าตัวอย่างแทนหน้าโมเดล
