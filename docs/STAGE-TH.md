**สาธิต 2026-11-21** อ่านไฟล์นี้ไฟล์เดียวพอในวันงาน

ตัวเลขที่วัดมาทุกตัวอยู่ใน [DEMO.md](DEMO.md) ซึ่ง **generate จากการรัน
pipeline จริง** ไฟล์นี้คือลำดับการเล่นและคำพูด ไม่ใช่แหล่งของตัวเลข

> **ตัดสินใจแล้วเมื่อ 2026-10-21: สาธิตจากโน้ตบุ๊กเป็นหลัก มือถือเป็นของแถม**
> เหตุผล: โน้ตบุ๊กรัน pipeline เต็มได้ `analysis_mode: full` คือ**สินค้าทั้งตัว**
> ส่วนมือถือได้แค่ `classifier_only` และต้องติดตั้ง PWA ซึ่งกินเวลาเตรียม
> โดยไม่ได้เพิ่มสิ่งที่กรรมการตัดสิน

## 1. ก่อนขึ้นเวที — สองหน้าต่าง

หน้าต่างแรก

```bash
cd backend && ./.venv/Scripts/python.exe -m uvicorn app.main:create_app --factory --port 8000
```

หน้าต่างที่สอง

```bash
cd frontend && npm run dev
```

เปิดเบราว์เซอร์ไปที่ **http://localhost:5173/scan**

### ตรวจสามข้อนี้ก่อนเริ่ม ใช้เวลาไม่ถึงนาที

```bash
curl -s http://127.0.0.1:8000/health
```

ต้องได้ `{"status":"ok","app":"TeaSmart AI","model_version":"teasmart-v1"}`

- หน้า `/scan` เรนเดอร์ภาษาไทย เห็นปุ่ม **เลือกภาพใบชา** และ **เปิดกล้อง**
- เปิดโฟลเดอร์ `demo/` ค้างไว้ จะได้ไม่ต้องหาไฟล์ตอนอยู่บนเวที

**ถ้า `/health` ไม่ตอบ** แปลว่า backend ไม่ได้รัน ไม่ใช่เรื่องใหญ่ เปิดใหม่
แล้วรอสองสามวินาที **อย่าขึ้นเวทีโดยไม่ได้เช็กข้อนี้**

## 2. ลำดับการเล่น หกภาพ

ใช้ปุ่ม **เลือกภาพใบชา** ทุกครั้ง **ไม่ต้องใช้กล้อง**

| ลำดับ | ไฟล์ใน `demo/` | สิ่งที่ต้องชี้ให้ดู |
|---|---|---|
| 1 | `01-brown-blight-severe.jpg` | ชื่อโรค ความเชื่อมั่น **คำตัดสิน `disease`** และ **ความรุนแรง `severe`** |
| 2 | `02-grey-blight.jpg` | โรคที่สอง ความรุนแรง `moderate` — ไม่ใช่กลลวงคลาสเดียว |
| 3 | `03-algal-spot.jpg` | โรคที่สาม คำแนะนำคนละชุดจากฐานความรู้ |
| 4 | `04-healthy.jpg` | ใบปกติ **ไม่ถูกตั้งชื่อโรค** และคำแนะนำคือไม่ต้องรักษา |
| 5 | `05-unsure-declines-to-name.jpg` | ความเชื่อมั่นต่ำกว่าเพดาน **ระบบปฏิเสธที่จะเดา** ตอบ `other_disease` |
| 6 | `06-blurry-asks-for-a-retake.jpg` | ด่านคุณภาพปฏิเสธ แล้วบอกเป็นภาษาไทยให้ถ่ายใหม่ |

### คำพูดที่สำคัญที่สุด อยู่ที่ภาพ 1

เมื่อการ์ดขึ้นครบ ให้พูดว่า

> นี่คือสิ่งที่สินค้านี้มีอยู่เพื่อมัน — **ไม่ใช่แค่บอกว่าเป็นโรคอะไร
> แต่แยกว่าเป็นโรคหรือเป็นแผลไหม้ทางกายภาพ** เพราะใบไหม้จากแดดหรือจากปุ๋ย
> ไม่ต้องฉีดยา การฉีดคือเสียเงินเปล่าและเพิ่มสารเคมีลงแปลงโดยไม่จำเป็น

### ภาพ 5 และ 6 คือจุดที่ทำให้ดูน่าเชื่อถือ ไม่ใช่จุดอ่อน

> ภาพที่ 5 โมเดลไม่มั่นใจพอ **มันจึงไม่ตั้งชื่อโรค** แทนที่จะเดาให้ดูเก่ง
> ภาพที่ 6 ภาพเบลอเกินไป **มันขอให้ถ่ายใหม่แทนที่จะวินิจฉัยจากภาพที่อ่านไม่ออก**
> การวินิจฉัยจากภาพที่อ่านไม่ออก แย่กว่าการไม่วินิจฉัยเลย

## 3. สาธิตออฟไลน์ บนโน้ตบุ๊กเครื่องเดิม

**ไม่ต้องใช้มือถือ ไม่ต้องติดตั้งอะไร**

ไปที่หน้าต่างที่รัน backend แล้วกด `Ctrl+C` ปิดมัน จากนั้นสแกนภาพเดิมซ้ำ

แอปจะย้อนไปรันโมเดลบนเครื่องเอง และการ์ดจะกำกับว่า **`classifier_only`**

พูดว่า

> ตอนนี้เซิร์ฟเวอร์ดับแล้ว แต่แอปยังตอบได้ เพราะโมเดลอยู่ในเบราว์เซอร์
> **และเป็นโมเดลตัวเดียวกัน** เราวัดเทียบ 50 ภาพ คำตอบอันดับหนึ่งตรงกันทั้ง 50
> และความน่าจะเป็นต่างกันมากที่สุด **0.00283 จากขอบที่ยอมรับได้ 0.05**
> ห่างจากขอบสิบแปดเท่า
>
> สิ่งที่หายไปตอนออฟไลน์**ไม่ใช่โมเดล แต่เป็นขั้นตอนแยกใบออกจากพื้นหลัง**
> ซึ่งทำได้เฉพาะบนเซิร์ฟเวอร์ จึงไม่มีคำตัดสินใบไหม้และไม่มีความรุนแรง
> **การ์ดบอกเรื่องนี้เองว่า `classifier_only`** เราไม่ปล่อยให้ใครเข้าใจผิดว่า
> ผลบนเครื่องเท่ากับผลเต็ม

อย่าลืมเปิด backend กลับถ้าจะสาธิตต่อ

## 4. สองข้อจำกัดที่ต้องพูดเอง ก่อนมีคนถาม

พูดตอนช่วงถาม-ตอบ หรือทันทีถ้ามีกรรมการขอถ่ายเอง

**ข้อแรก ใบที่ปกติดีถูกตั้งชื่อโรคได้**

> ทดสอบบน iPhone เมื่อวาน ภาพมือกำยอดชาสดเขียวสมบูรณ์ ได้ `brown_blight`
> ที่ **92.4%** ตัวเลขความแม่น 0.987 ของเราวัดบนชุดทดสอบที่เป็น**ภาพโคลสอัพ
> ใบเดี่ยว** ภาพจริงที่มีหลายใบ มีมือ มีพุ่มชาเป็นฉากหลัง อยู่นอกการกระจายนั้น
> **0.987 จึงเป็นขอบบน ไม่ใช่ค่าประมาณในสนาม**

**ข้อสอง ภาพที่ไม่ใช่ใบไม้ก็ได้ชื่อโรค**

> ตัวจำแนกมีห้าคลาสปิด ไม่มีทางปฏิเสธ **ทุกภาพถูกบังคับให้เป็นหนึ่งในห้าคลาส**
> ภาพถ่ายหน้าจอคอมพิวเตอร์ได้ `brown_blight` ที่ 76.8% ทางแก้คือ open-set
> rejection ซึ่งอยู่ในแผนงานถัดไป **ไม่ใช่การปรับค่า threshold**

**การพูดสองข้อนี้เองทำให้น่าเชื่อถือขึ้น ไม่ใช่ลดลง** กรรมการที่ลองแล้วเจอเอง
โดยที่เราไม่ได้บอกไว้ จะสรุปว่าเราไม่รู้จักสินค้าตัวเอง

## 5. ตัวเลขที่อ้างได้ และที่ห้ามอ้าง

**อ้างได้**

| | |
|---|---|
| คลังภาพ | 8,316 ภาพ ห้าคลาส แบ่ง 70/15/15 ตรวจซ้ำข้ามชุดแล้วพบ 0 คู่ |
| ความแม่นบนชุดทดสอบ | 0.9871 · macro-F1 0.9873 |
| ใบเป็นโรคถูกเรียกว่าปกติ | 0 จาก 584 |
| specificity ของตัววิเคราะห์ใบไหม้ | 97.18% บนภาพโรค 1,030 ภาพ |
| parity เบราว์เซอร์กับเซิร์ฟเวอร์ | 50/50 ตรงกัน delta สูงสุด 0.00283 |

**ห้ามอ้างเด็ดขาด**

- **ค่า sensitivity ของการตรวจใบไหม้** — ไม่มีอยู่ ไม่มีภาพใบไหม้ที่มีป้ายกำกับ
  ในแหล่งข้อมูลทั้งเก้าที่สำรวจ **ถ้าถูกถาม ให้ตอบว่าวัดไม่ได้และบอกว่าทำไม**
- **ว่า 0.987 คือความแม่นในสนาม** — มันคือขอบบน
- **ว่าเคยทดสอบที่สิงห์ปาร์ค** — ไม่มีภาพใดในคลังมาจากที่นั่น

ถ้าถูกถามว่า specificity 97.18% สูงไปไหม **ตอบตรง ๆ ว่าการรันครั้งแรกได้
99.22% ขณะที่หาแผลไม่เจอบนใบที่เป็นโรค 59% เราจึงแก้ mask แล้ววัดใหม่**
คำตอบนี้แสดงว่าเราตรวจสอบการวัดของตัวเอง

## 6. ถ้ามีอะไรพัง

| อาการ | ทำอะไร |

| `/health` ไม่ตอบ | เปิด backend ใหม่ รอสองวินาที อย่าตกใจ |

เป็นของแถม ถ้าอินเทอร์เน็ตในห้องล่ม การสาธิตนี้**ยังทำงานได้ทั้งหมด**
เพราะไม่มีอะไรวิ่งออกนอกเครื่อง

## 7. สิ่งที่ไม่ต้องทำ

- **ไม่ต้องติดตั้ง PWA บนมือถือ** ไม่ต้องโหลด 30.7 MB ไม่ต้องล้างแคช Safari
- **ไม่ต้องถ่ายพุ่มชาหรือกำใบโชว์** ภาพแบบนั้นอยู่นอกการกระจายของโมเดล
  และจะได้คำตอบผิดแบบมั่นใจ ตามข้อ 4
- **ไม่ต้องใช้กล้องบนเวที** ใช้ **เลือกภาพใบชา** จาก `demo/` ซึ่งเร็วกว่า
  และควบคุมได้
- **ไม่ต้องยื่น QR ให้กรรมการ เว้นแต่มีคนขอ** ถ้าขอก็ยื่นได้ แต่บอกก่อนว่า
  รุ่นบนเว็บไม่มีคำตัดสินใบไหม้และไม่มีความรุนแรง
