#### เทสต์ที่ต้องมี

- ภาพที่เป็นพื้นสีเดียวไม่ใช่เขียว → `passed: false` และได้ `detail_th`

  เหตุผลที่ด่านนี้วางไว้ตรงนั้น
- การกลายพันธุ์ที่ต้องทำให้เทสต์แดง: กลับทิศเปรียบเทียบ threshold ·

#### สิ่งที่ไม่ใช่งานของคุณในข้อนี้

### I. worker กลืนข้อความ error จริงทิ้งทั้งหมด — เจอระหว่างตรวจข้อ H

`frontend/src/lib/onnx-worker.ts` บรรทัดสุดท้าย:

`โมเดลไม่ตรงกับการตั้งค่า` **ทั้งสามเคสผู้ใช้เห็นว่า "กรุณาเตรียมใช้งาน

เทสต์: ทำให้ `load` ล้มเหลวแล้วยืนยันว่าข้อความที่ถึง `inferOffline`

### A. เปิดกล้องแล้วปิดไม่ได้ — ผู้ใช้รายงาน ตรวจยืนยันแล้ว

`frontend/src/pages/ScanPage.tsx` บรรทัด 123-124 เป็น ternary


**ตอนกล้องเปิด ปุ่มเดียวที่เรนเดอร์คือ `ถ่ายภาพ` ไม่มีปุ่มปิดอยู่เลยทั้งหน้าจอ**

`stopCamera()` (บรรทัด 22) เขียนไว้ถูกต้องและหยุด track ครบ **แต่ไม่มีทางเรียก
จาก UI ได้** ผู้ใช้ที่กดเปิดกล้องแล้วเปลี่ยนใจ มีทางออกแค่สองทาง: ถ่ายรูป
หรือเลือกไฟล์จากเครื่อง

**ทำไมมันหนักกว่าความรำคาญ** สตรีมกล้องยังเปิดอยู่ ไฟแสดงสถานะกล้องยังติด
และบน iOS จุดเขียวบน Dynamic Island ยังค้าง **กรรมการจะรู้สึกว่าแอปไม่ยอม
ปล่อยกล้อง** ซึ่งเป็นความรู้สึกเรื่องความเป็นส่วนตัว ไม่ใช่แค่ UX
และมันกินแบตด้วย

**แก้:** เพิ่มปุ่ม `ปิดกล้อง` ตอน `camera === true` ที่เรียก
`stopCamera(); setCamera(false);` **ให้ `ถ่ายภาพ` ยังเป็นปุ่มหลักอยู่**
คอมเมนต์เหนือบล็อก `.actions` อธิบายไว้แล้วว่าทำไมการถ่ายต้องเป็น primary
ตอนกล้องเปิด — อย่าไปสลับลำดับนั้น

**test ที่ต้องแดงก่อน:** เปิดกล้อง กดปิด แล้ว assert ว่า track ทุกเส้นถูก
`stop()` และ UI กลับไปแสดงปุ่ม `เปิดกล้อง` ใช้ mock ของ `getUserMedia`
ที่สอดแนมการเรียก `stop()` ได้

ถ้าเซิร์ฟเวอร์ตอบ 500 หรือ 503 entry จะคง `pending` **และถูกส่งซ้ำทุกครั้งที่
`revision` ขยับ ไม่มี backoff ไม่มีตัวนับครั้ง ไม่มีเพดาน**
ตั้งใจให้ retry ข้อผิดพลาดชั่วคราวซึ่งถูก แต่ไม่มีทางออกถ้ามันไม่ชั่วคราว

**แก้:** นับจำนวนครั้ง เกิน N แล้วทำเป็น `failed` พร้อมข้อความไทย

### 12. `enqueue` และ `applyBatch` เก็บ object ดิบ ส่วน `save` เก็บค่าที่ผ่าน `parseStored`

```js
save:       put('scans', parseStored(result))   // เก็บค่าที่ return
enqueue:    parseStored(result); put('scans', result)   // ทิ้งค่าที่ return
applyBatch: results.forEach(parseStored); put('scans', result)  // ทิ้งเช่นกัน
```

ถ้า `parseStored` ทำแค่ตรวจ ก็ไม่ต่างกัน **แต่ถ้ามันปรับรูปอะไรสักอย่าง
สองเส้นทางนี้จะเก็บคนละรูป** ให้ทำให้เหมือนกันทั้งสามที่ ไม่ว่าคำตอบจะเป็นทางไหน

### 13. `resize.ts` ส่ง helper ที่ใช้เฉพาะตอนทดสอบขึ้นเว็บไปด้วย

`pixelByte` และ `sourceImage` มีคอมเมนต์เขียนไว้เองว่า *"Test-only; the app
never calls this"* แต่ถูก `export` จากโมดูลที่ `inference.ts` import
**ตรวจว่า rollup tree-shake มันออกจริงหรือไม่ อย่าเดา** ถ้าไม่ออก ให้ย้ายไป
ไฟล์แยกใต้ `src/test/` ความสำคัญต่ำสุดในรายการนี้

## 3. ปัญหาที่ยังเหลือก่อนสาธิต เรียงตามความสำคัญ

### ต้องเสร็จก่อนขึ้นเวที

**P0-1 · deploy static — เตรียมครบ รอเลือก host · เจ้าของ: ผู้ใช้ + คุณ**
ขั้นตอนครบใน [docs/DEPLOY-TH.md](DEPLOY-TH.md) ตัดสินใจแล้วว่า deploy
**เฉพาะ frontend ไม่ deploy backend** เพื่อให้กรรมการสแกน QR เปิดบนมือถือตัวเอง
ไม่ต้องติดตั้งอะไร และรูปไม่ออกจากเครื่องกรรมการ
ลำดับคือ: รัน backend → `python scripts/snapshot_api.py` → `npm run build` → อัปโหลด `dist`
**ห้าม build โดยไม่ snapshot ก่อน**

**P0-2 · สแกนหลังติดตั้ง PWA แล้วปิดเน็ต ยังไม่มีใครวัด · เจ้าของ: คุณ**
นี่คือสไลซ์ของคุณตรง ๆ และเป็นข้อที่กรรมการตัดสิน
ไฟล์ snapshot ไม่มีนามสกุล จึงไม่เข้า `globPatterns` ของ VitePWA และ build ยังรายงาน
**precache 13 entries** เท่าเดิม service worker จึงไม่ได้ precache `config` กับ `kb`
ผลขึ้นกับว่าปุ่ม `เตรียมใช้งานออฟไลน์` เก็บ config ไว้เองหรือไม่ — **ยังไม่มีใครกดวัด**
ถ้าไม่ผ่าน ทางแก้คือเพิ่มสองไฟล์เข้า precache หรือให้ปุ่มนั้นเก็บลง IndexedDB
**วัดก่อนแก้** และถ้าเพิ่มเข้า precache ให้ตรวจว่าจำนวน entries เปลี่ยนจริง

**P0-3 · `_redirects` ยังไม่ยืนยัน · เจ้าของ: คุณ หลัง deploy**
`python -m http.server` ไม่อ่านไฟล์นี้ `/kb` จึงตอบ 404 ตอนทดสอบในเครื่อง
Cloudflare Pages และ Netlify อ่านเอง แต่ยืนยันได้หลัง deploy จริงเท่านั้น
ทางเข้าหลักไม่พึ่งมันเพราะ `App.tsx` ส่ง route `*` ไป `/scan` อยู่แล้ว
**QR ต้องชี้ไป root ไม่ใช่ `/scan`**

**P0-4 · รันบนมือถือจริง ยังไม่มีผล · เจ้าของ: ผู้ใช้**
ผู้ใช้ติดตั้ง root CA บน iPhone แล้วและกำลังเปิดแอปตอนจบวัน
ยืนยันจากเครื่องผู้ใช้แล้วว่า `/scan` = 200, `/api/v1/config` = 200, CA server = 200
แต่**ข้อ 1-7 ใน [docs/PHONE-TH.md](PHONE-TH.md) ยังไม่มีใครยืนยันแม้ข้อเดียว**

### P2 — เป็นของ `frontend/` ทั้งสองข้อ

**P2-1 · `src/lib/api.ts` hard-code รายชื่อคลาส**
ซ้ำกับที่ `GET /api/v1/config` เสิร์ฟ วันนี้ค่าตรงกัน **การมีสำเนาที่สองคือตัวปัญหา**

**P2-2 · `parseKnowledge` บังคับให้มี record เท่ากับ 6 รายการพอดี**
โรคที่เจ็ดจะทำให้ client พัง `scripts/snapshot_api.py` มี test ที่เฝ้าเรื่องนี้ฝั่ง backend แล้ว
แต่ฝั่ง client ยังพัง

**P2-3 · `TEASMART_CORS_ORIGINS`**
ต้องตั้งถ้า PWA ที่ build ถูกเสิร์ฟจาก origin อื่นที่ไม่ใช่ `localhost:5173`
**แผนที่เลือกไว้คือ static-only จึงไม่มี backend และข้อนี้ไม่มีผล** แต่ถ้าเปลี่ยนใจ
ไป deploy backend ด้วย ข้อนี้กลับมาทันที dev proxy ปิดปัญหานี้ไว้ จะไม่เห็นในเครื่อง

## 4. ตัวเลขที่พูดผิดแล้วเสียหาย

- **ไม่มีค่า sensitivity ของการตรวจใบไหม้ และห้ามอ้าง รวมถึงบนเวที**

- **ไม่มีภาพใดในคลังมาจากสิงห์ปาร์ค**
- **threshold ของด่าน 1 และ `min_confidence` วัดมาแล้ว — วัดใหม่ ห้ามขยับมือ**
