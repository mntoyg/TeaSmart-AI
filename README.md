# TeaSmart AI

ผู้ช่วยเกษตรแม่นยำสำหรับไร่ชาอู่หลง **ถ่ายรูปใบชาหนึ่งใบ** ระบบบอกชื่อโรค
ระดับความรุนแรง **ตัดสินว่าเป็นโรคหรือเป็นแผลไหม้ทางกายภาพ** และให้คำแนะนำ
การรักษาเป็นภาษาไทยจากฐานความรู้ที่คัดมา

โมเดลรันอยู่บนเครื่องผู้ใช้ **จึงทำงานต่อได้แม้ไม่มีสัญญาณ** ซึ่งเป็นเงื่อนไขจริง
ของไร่ชาบนภูเขา

Phase 1 MVP สาธิตแฮกกาธอน **2026-11-21**

## **https://teasmart-ai.pages.dev**

**เป็นเว็บแอป ไม่ต้องติดตั้งอะไรทั้งสิ้น** ไม่มีใน App Store ไม่มีใน Play Store
และไม่จำเป็นต้องมี กดลิงก์หรือสแกน QR จากมือถือเครื่องไหนก็ได้ แล้วใช้ได้ทันที

ไม่ต้องลงใบรับรอง ไม่ต้องตั้ง flag ไม่ต้องต่อสาย ไม่ต้องอยู่ wifi วงเดียวกัน
และ**ไม่ต้องสมัครอะไร**

## ถ่ายอย่างไรให้ได้ผลที่ถูกต้อง

**ใบเดียว โคลสอัพ ให้เต็มกรอบ** แสงธรรมชาติ ไม่มีเงาทับ

โมเดลเรียนจากภาพใบเดี่ยวระยะใกล้ทั้งหมด **ภาพพุ่มชา ภาพมือกำใบหลายใบ หรือภาพ
ถ่ายไกล อยู่นอกสิ่งที่มันเคยเห็น** และจะให้คำตอบที่ผิดโดยที่ยังดูมั่นใจ
อ่านหัวข้อข้อจำกัดข้างล่างก่อนสรุปผลที่ได้

สองช่องที่เว็บทำไม่ได้ต้องใช้ขั้นตอนแยกใบออกจากพื้นหลัง ซึ่งรันบนเซิร์ฟเวอร์
**สาธิตสองอย่างนั้นจากโน้ตบุ๊กบนเวที**

## ข้อจำกัดที่เราบอกเอง ก่อนมีคนถาม

**ใบที่ปกติดีถูกตั้งชื่อโรคได้ ที่ความมั่นใจสูง** ทดสอบบน iPhone เมื่อ 2026-10-21
ภาพมือกำยอดชาสดเขียวสมบูรณ์ ได้ `brown_blight` ที่ **92.4%** เพราะภาพแบบนั้น
อยู่นอกการกระจายของชุดเทรน

**ภาพที่ไม่ใช่ใบไม้ก็ได้ชื่อโรค** ตัวจำแนกมีห้าคลาสปิด ไม่มีทางปฏิเสธ
ทุกภาพจึงถูกบังคับให้เป็นหนึ่งในห้าคลาส ภาพถ่ายหน้าจอคอมพิวเตอร์ได้
`brown_blight` ที่ 76.8% ทางแก้คือ open-set rejection ซึ่งเป็นข้อแรกใน
[docs/AI-ROADMAP.md](docs/AI-ROADMAP.md)

**ไม่มีภาพใดในคลังมาจากสิงห์ปาร์คหรือไร่ชาไทยใด ๆ** ยังไม่เคยทดสอบบนไร่จริง
ที่สินค้านี้ถูกสร้างขึ้นมาเพื่อมัน

**ไม่มีค่า sensitivity ของการตรวจใบไหม้ และเราจะไม่อ้างตัวเลขนั้น**
เพราะไม่มีภาพใบไหม้ที่มีป้ายกำกับในแหล่งข้อมูลทั้งเก้าที่สำรวจ

รายการเต็มพร้อมแผนแก้อยู่ใน [docs/PRODUCTION-READINESS.md](docs/PRODUCTION-READINESS.md)

## สถาปัตยกรรม

ภาพหนึ่งใบเดินผ่านหกด่าน แต่ละด่านเป็นฟังก์ชันบริสุทธิ์คนละโมดูล **ไม่มีด่านไหน
เอื้อมไปแก้ของอีกด่าน**

```
ภาพ -> [1] ด่านคุณภาพ -> [2] แยกใบออกจากพื้น -> [3] จำแนกโรค
     -> [4] วิเคราะห์แผล (โรค vs ไหม้) -> [5] ความรุนแรง -> [6] ระบบผู้เชี่ยวชาญ
```

สามเรื่องที่สำคัญที่สุด เหตุผลเต็มอยู่ใน [docs/DESIGN.md](docs/DESIGN.md)

- **โมเดลเรียนห้าคลาส** `grey_blight`, `brown_blight`, `algal_spot`, `healthy`,
  `other_disease` — ส่วน `physical_burn` **ไม่ใช่คลาสที่โมเดลเรียน** เพราะไม่มี
  ชุดข้อมูลรูปใบไหม้ที่มีป้ายกำกับอยู่ที่ไหนเลย ด่าน 4 จึงเป็น CV แบบกฎเกณฑ์
  ตัวชี้วัดหลักคือ specificity บนรูปที่ยืนยันว่าเป็นโรค
- **`other_disease` มีไว้โดยเจตนา** ให้โมเดลพูดได้ว่า "ผิดปกติแต่ไม่ตรงโรคหลัก
  ให้นักวิชาการเกษตรดู" แทนที่จะทายชื่อโรคผิดอย่างมั่นใจ
- **เส้นทางหลักคือ ONNX บนเครื่องผู้ใช้** เซิร์ฟเวอร์เป็นส่วนเสริม ผลบนเครื่อง
  ถูกกำกับ `classifier_only` เพราะเบราว์เซอร์ไม่แยกใบออกจากพื้น

ขอบเขตระหว่าง frontend กับ backend คือสัญญา API ใน `docs/DESIGN.md` หัวข้อ 8
ค่าคงที่ที่ใช้ร่วมกันเสิร์ฟจาก `GET /api/v1/config` — **อย่า hard-code**

# สำหรับนักพัฒนา

## ติดตั้งและทดสอบ

```bash
./scripts/setup.sh --cpu     # Linux, macOS; ตัด --cpu ออกถ้ามีการ์ด NVIDIA
./scripts/test.sh
```

```powershell
./scripts/setup.ps1 -Cpu     # Windows; ตัด -Cpu ออกถ้ามีการ์ด NVIDIA
./scripts/test.ps1
```

ต้องมี Python 3.12 และ Node 22 **ไม่มีอะไรต้องใช้ `.env` เพื่อรัน** คัดลอก
`.env.example` ไปเป็น `backend/.env` เฉพาะเมื่อต้องการเปลี่ยนค่าตั้งต้น
ไม่ต้องใช้ความลับใด ๆ

## รันให้ครบทั้ง pipeline

```bash
cd backend && .venv/bin/python -m uvicorn app.main:create_app --factory --reload
```

```bash
cd frontend && npm run dev     # http://localhost:5173/scan
```

บน Windows ตัวแปลภาษาคือ `.venv/Scripts/python.exe` แทน
Vite ส่งต่อ `/api` ไปที่ `http://127.0.0.1:8000` ทั้งสองฝั่งจึงคุยกันได้โดยไม่ต้อง
ตั้ง CORS ในเครื่องพัฒนา **แบบนี้จะได้ `analysis_mode: full` คือครบทั้งหกด่าน**

ขั้นตอนสาธิตทีละภาพอยู่ใน [docs/STAGE-TH.md](docs/STAGE-TH.md)

## สร้าง QR ใหม่เมื่อ URL เปลี่ยน

```bash
python scripts/make_qr.py https://<โฮสต์>/
```

README ไม่ต้องแก้ เพราะชี้ไป path คงที่ script จะ**ปฏิเสธ** URL ที่เป็น localhost
หรือวง LAN โดยอัตโนมัติ เพราะ QR แบบนั้นทำงานบนมือถือคนทำแต่พังสำหรับคนอื่น
ซึ่งแย่กว่าไม่มี QR

## โครงสร้างโฟลเดอร์

```
backend/        FastAPI: รับภาพ, ด่านของ pipeline, ระบบผู้เชี่ยวชาญ
  app/api/v1/     ผิว HTTP หนึ่งโมดูลต่อหนึ่งกลุ่ม endpoint
  app/core/       config และประตูบานเดียวที่ภาพทุกใบต้องผ่าน
  app/services/   หนึ่งโมดูลต่อหนึ่งด่าน แต่ละตัวเป็นฟังก์ชันบริสุทธิ์
  app/kb/         ฐานความรู้โรคภาษาไทย (เป็นข้อมูล ไม่ใช่โค้ด)
ml/             ชุดข้อมูล, เทรน, ประเมิน, ส่งออก ONNX
  teasmart_ml/    `python -m teasmart_ml.cli --help`
frontend/       PWA ที่รันโมเดลบนเครื่องผู้ใช้
docs/           เอกสารทั้งหมด ไม่มีโฟลเดอร์ย่อย
scripts/        setup, test, สร้าง QR, snapshot API, เตรียมชุดสาธิต
data/           ชุดข้อมูลและไฟล์กลาง ไม่ commit
private/        ของเฉพาะเครื่อง ไม่ commit
```

แต่ละแพ็กเกจ Python มี virtualenv และ `pyproject.toml` ของตัวเอง และ**ไม่เคย
activate** ทุกคำสั่งระบุตัวแปลภาษาตรง ๆ จึงไม่มีอาการ "ตอนนี้อยู่ venv ไหน"
